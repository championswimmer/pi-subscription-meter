2. Interpret the requested `+0.1` increment using the repo's prior release precedent: a semver minor bump from `0.3.1` to `0.4.0`.
3. Update `package.json` and `package-lock.json` to `0.4.0` without auto-creating a git tag so the commit/push/tag order can match the request.
4. Run validation (`npm run typecheck`) and review status/diff to ensure the release bundle includes the current Codex work plus relevant plan files.
5. Commit the full worktree with a focused release message, then push `main` first.
6. After the branch push succeeds, create an annotated `v0.4.0` tag pointing at the release commit and push that tag separately.
7. Update this plan with the commands run, validation results, and the final commit/tag identifiers.
