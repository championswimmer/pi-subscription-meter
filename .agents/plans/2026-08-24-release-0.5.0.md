# Release package version 0.5.0

## Status
Release candidate validated

## Objective
Bump `pi-subscription-meter` from `0.4.0` to the next requested `+0.1.0` minor version, `0.5.0`, commit the release metadata and this plan, push `main`, then create and push the `v0.5.0` tag. The user will publish to npm manually after the tag is available.

## Checklist
- [x] Confirm the clean `main` worktree, current version (`0.4.0`), latest release tag, npm availability, and git identity.
- [x] Run `npm version minor --no-git-tag-version` to update `package.json` and `package-lock.json` to `0.5.0` without committing before the release plan can be included.
- [x] Validate the version and TypeScript release candidate.
- [ ] Review the staged release-only diff and create the release commit.
- [ ] Push the release commit to `origin/main`.
- [ ] Create annotated tag `v0.5.0` on the pushed commit and push it to `origin`.
- [ ] Update this plan with the final commit, tag, push, and validation outcomes.

## Detailed implementation plan
1. Interpret the requested `+0.1.0` increment as the semantic-version minor bump `0.4.0` → `0.5.0`, matching the repository’s prior `0.3.1` → `0.4.0` release convention.
2. Run the npm version command with `--no-git-tag-version`. This is still npm’s authoritative version/lockfile update, while retaining control over the release commit so the required plan is included and the tag is created only after `main` is pushed.
3. Check that both package manifests report `0.5.0`, run `npm run typecheck`, and use `git diff --check` to validate the release candidate.
4. Stage only `package.json`, `package-lock.json`, and this plan; create a focused `release: v0.5.0` commit and push it to `origin/main`.
5. Create annotated tag `v0.5.0` targeting that pushed release commit and push the tag to `origin`.
6. Update this plan with the exact commit/tag and validation results. Do not run `npm publish`; the user will publish manually.

## Risks / questions
- `npm version` defaults to committing/tagging and requires a clean worktree. The `--no-git-tag-version` option is intentional to preserve the repository’s plan-before-change requirement and the requested push-before-tag order.
- Publishing credentials and `npm publish` are outside this task and will not be invoked.

## Validation
- `node -p "require('./package.json').version"` reports `0.5.0`
- `npm run typecheck`
- `git diff --check`
- `git push origin main`
- `git tag -a v0.5.0 -m "v0.5.0"`
- `git push origin v0.5.0`
